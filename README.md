# Продуктовая аналитика маркетплейса Olist

Учебный проект: когортный анализ удержания, оценка признаков соответствия продукта рынку, выбор продуктовых метрик, приоритизация гипотез по ICE и план будущего A/B-теста.

**Историческая выгрузка не содержит результатов эксперимента.** Проект предлагает проверку гипотезы, а не доказывает эффект её внедрения.

**Статус: приватный проект до проверки разрешений на публикацию.** Исходные CSV и выполненный ноутбук хранятся отдельно. Лицензия на распространение материалов не предоставляется.

## Задача и подход

По условиям кейса выручка маркетплейса не растёт. Исторические заказы используются для диагностики повторных покупок и выбора направления исследования; доход платформы и прибыль напрямую не измерены.

- Проверка уникальности ключей, пропусков и корректности объединения таблиц.
- Месячные когорты по первой успешно доставленной покупке, определённой по дате оформления.
- Разделение наблюдаемого нулевого удержания и будущих ненаблюдаемых периодов.
- Проверка чувствительности к неполному последнему месяцу и малым ранним когортам.
- Анализ GMV, активных покупателей, повторных покупок и среднего оборота на покупателя.
- Сравнение трёх гипотез по заданной учебной модели ICE.
- План эксперимента с целевой, прокси и защитными метриками и учётом зависимости заказов одного клиента.

## Результаты и ограничения

Проверенные расчёты и статус запуска приведены в `VALIDATION.md`. Низкий retention сам по себе не доказывает отсутствие PMF: покупки могут быть редкими. GMV не равен доходу или прибыли платформы. Оценки дополнительных заказов в ICE — сценарные допущения, а не доказанный эффект. Для причин отмен, расходов, посещений и платёжных ошибок нужны дополнительные источники.

Особенность определения retention: учитываются заказы со статусом `delivered`, месяц события берётся по дате оформления. Это удержание по оформлению впоследствии доставленных заказов, а не по всем попыткам оформления. Если требуется retention всех попыток, определение события следует согласовать отдельно.

## Запуск

Из корня проекта в Python 3.9:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyterlab
```

Для Windows PowerShell активация: `.venv\Scripts\Activate.ps1`.

Поместите три CSV в `data/private/`, откройте `olist_marketplace_analysis.ipynb` и выполните **Restart Kernel and Run All Cells**. Без данных воспроизведение невозможно. Перед добавлением ноутбука в Git очистите все выводы ячеек.
